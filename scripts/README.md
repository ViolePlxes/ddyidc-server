# 部署入口变更

旧 `scripts/install.sh` 已停用，运行立即退出 2，不执行用户创建、软件安装、数据库授权、密钥写入或服务重启。历史实现保留在文件中供审查，禁止绕过入口保护后执行。

旧流程的 Go 1.22 与应用 `GRANT ALL` 不满足当前基础建设要求；不要继续使用旧版远程 `curl | bash` 命令，也不要将 GitHub token 放进命令行参数。

受支持入口见 [Linux 部署说明](../deploy/linux/README.md)：

1. 按文档安装固定版本工具链，在可信检出上执行 `deploy/linux/build-linux.sh`，保存版本、提交与产物校验和。
2. 新机器使用 `deploy/linux/install.sh`；它拒绝已有配置和中断的初始化状态，先离线迁移，再创建受限运行账号。
3. 已有机器使用离线版本迁移与独立程序目录迁移流程，不重复执行全新安装。保存程序/配置回退副本，业务数据恢复另行授权。
4. 凭据继续使用私有文件或受控凭据代理，不写入 Git、日志或交付记录。

当前整改仍在验收中：已在空白 VM 验证离线迁移、在主 VM 验证程序目录迁移；完整新装流程不能据此宣称已通过。
