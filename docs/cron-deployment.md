# 后台定时任务的多实例与环境隔离

全部后台循环由 `internal/shared/distsync` 的全局领导锁控制。HTTP 路由和手动业务接口不受领导权影响。

```yaml
Cron:
  Enabled: true
```

旧配置未包含 Cron 时默认 true。配置 `Cron.Enabled: false` 或命令行 `--no-cron` 完全跳过所有任务启动入口；命令行优先。启动日志明确标记关闭状态，API/health 保持工作。新配置项不改变业务表结构。

## 锁与故障行为

- 共用 Redis 的所有实例竞争同一个 `ddyidc:cron:leader`，不按实例命名。随机 token、30 秒租约、10 秒心跳，Lua 校验 token 后续期/删除。follower 每 250ms 重新竞争；异常退出后租约到期接管，正常退出可释放。
- 领导权丢失时取消本轮任务上下文，重新获得后启动下一轮循环。高频更新结果观察和余额通知仅检查进程内领导状态；通知/对账、拼团、CDN 四个扫描、交易市场、积分执行前增加 `ddyidc:lock:<task>` 任务锁。任务锁一分钟租约、持续续期、token 校验释放；忙则跳过。
- CDN P2 队列仍使用已有数据库状态机，不加任务锁；其整个循环仍受领导启动/关闭开关控制。交易市场内部交易锁保留。
- 生产整改后 Redis 故障采用**失败关闭**：停止新任务领取，领导续租失败取消该轮上下文，任务锁续租失败也取消任务上下文；恢复后重新竞争。此变更覆盖旧版故障放行要求，HTTP 功能入口不因此隐藏。取消上下文不能撤销已经发生的远端操作，也不能约束忽略 context 的旧执行者，后续仍须逐业务持久化状态和租约版本保护。无法通过 Redis 分布式租约提供任意网络分区下的 exactly-once；重要业务仍依赖既有数据库状态机、事务与幂等键。
- 接管时间受剩余租期、250ms 竞争轮询与运行时调度影响，通常小于 30 秒；30 秒是租约值，不能承诺操作系统长暂停/网络故障情况下绝对不超过 30 秒。
- Redis 在进程启动之前就不可用时，现有缓存初始化仍会拒绝启动；失败关闭策略适用于服务运行中 Redis 故障，不绕过认证/缓存初始化约束。

## 环境纪律

测试必须使用独立 MySQL 库、独立 Redis（或独立 DB index）和独立更新结果目录，禁止连接生产库执行写操作。二机测试固定使用 `--no-cron` 加测试库。即使误连生产 Redis，正常持有领导锁的生产实例会阻止测试实例启动扫描，但不能把它视为环境隔离替代品；生产重启或 Redis 故障时测试实例可能取得执行权。

本次 VM 验收使用 VM 测试数据库和临时独立 Redis（6382），两个完整后端进程共用它验证全局互斥；测试后停止临时进程与 Redis，移除含凭据的临时配置。云机未部署。

## 验证

`go test ./...`、`go vet ./...`、`go build ./...`。`go test -race ./internal/shared/distsync` 会启动本机临时 Redis（随机回环端口、不持久化），验证 token 防误删、并发互斥、长任务续期、丢锁取消、Redis 故障/恢复、领导切换及配置默认值。没有安装 redis-server 的环境跳过真实 Redis 测试，CI 应安装 Redis 以完整执行。

官方依据：[Redis 单实例锁、token 校验释放与续租](https://redis.io/docs/latest/develop/clients/patterns/distributed-locks/)。真实 etc/config.yaml 被仓库忽略以保护凭据，交付 etc/cron.example.yaml 供合并。
