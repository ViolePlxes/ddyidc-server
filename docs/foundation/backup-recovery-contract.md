# F07 业务备份与恢复边界（实施中）

## 备份范围

业务 OSS 包仅包含 agency/billing/common/customer/instance/marketing/order/payment/product/system/ticket 的逻辑备份与 storage。
不包含 mysql 系统账户库、Redis 会话、config.yaml 或 secrets。
维护屏障 system.operation_barrier 是运行控制状态，排除在业务恢复之外，不能被旧快照重新打开。
本地 root 灾难备份与 OSS 业务包是独立产物，前者不由业务上传器上传。

## 新格式

版本 2 清单包含文件 SHA256、AES 密钥指纹、数据库迁移清单及校验和、备份起止时间、ID 分配高水位、可取得的二进制版本身份。
应用身份以已安装 `/opt/ddyidc/bin/ddyidc-server` 的 SHA256 为准，工作器自身构建信息独立记录，避免误把工作器的 `(devel)` 当作应用版本。备份开始/结束产物不同则失败；自动恢复要求同一应用产物及完整一致的迁移清单。不同应用版本必须先在隔离环境核验并离线恢复，不能只因 schema 相同就自动判定兼容。
清单以独立的 root0600 `/etc/ddyidc/secrets/backup-signing.key` 进行带用途前缀的 HMAC-SHA256 认证；应用 AES 密钥只用于兼容性指纹，不能伪造恢复归档。两类密钥均不进入 OSS 备份。
安装时运行 `deploy/linux/prepare-backup-maintenance.sh`，只初始化不存在的签名密钥，不覆盖已有密钥。签名密钥必须单独离线保管；丢失后不能自动恢复原归档。
单纯篡改 SQL 再重算公开文件哈希不能通过认证。签名验证不能代替数据库/文件一致性协议。
旧版本 1 包仍可下载保管，但因缺乏认证与迁移证据，不允许直接进入自动恢复；须在隔离环境人工核验和迁移。

恢复前可用 root 运行 `ddyidc-backup-worker --verify-oss <备份UUID>`：强制忽略本地副本，从原私有 Bucket 下载，核对归档哈希、独立签名、AES 指纹、迁移及应用产物身份。临时校验文件清理；不导入 SQL、不锁运行账户、不改变维护屏障、不启动业务。该命令通过仅证明归档校验，不等于实际恢复验收通过。

## 特权维护与恢复放行

工作器使用本地 Unix socket 的独立维护身份；仅允许隔离指定 `ddyidc_runtime` 应用身份，不能锁定root。逻辑包不含mysql身份库。
恢复工作目录、回滚副本和journal位于root独占的 `/var/lib/ddyidc-maintenance/`，不能放在应用可替换的父目录下。日志阶段与结果原子写入并fsync。
在导入前记录账户原状态，先持久关闭维护屏障并等待已受理工作退出，再锁定应用身份并切断已有连接。失败或成功都不自动解锁，不自动重启服务；存在未放行journal时禁止继续自动备份/恢复。
恢复前记录收款、退款、采购、续费、实例、订单、余额和流水事实；导入后生成差异清单。ID高水位不倒退，pending/running持久任务转unknown，不能重放潜在外部副作用。
运维人工核对第三方事实，在root维护目录中的 `reconciliation.json` 逐项记录处理结果；再次比对当前事实，拒绝核对后产生的新差异，余额对账也须通过。
显式放行命令为 `ddyidc-backup-worker --release <任务UUID> --confirmation '已完成外部对账 <任务UUID>' --operator <操作人> --reason <原因>`。放行前核对屏障属于当前恢复；放行记录持久化后恢复原先未锁定的账户并打开屏障。本机已停止服务仍须运维检查后启动；其他仍运行节点会在屏障打开后恢复受理。
该确认文字是运维对外部核对结果的声明，不是假定本地SQL能证明支付平台或供应商事实。中断于导入/未知阶段禁止直接放行，先修复或回滚。

附件快照和物理垃圾回收共用数据库连接锁；复制通过固定根目录句柄，拒绝越界路径、符号链接及特殊文件。单元/隔离锁测试不等同于真实OSS并发恢复验收。

## 全节点排空（候选接入，整体验收未完成）

维护控制连接池独立于业务池，避免每个请求持有控制连接却耗尽执行自身业务所需连接。
正常操作持有共享行锁，维护转换等待所有节点已受理操作退出后持久写入暂停状态。
恢复之后不能自动将状态改回 running。必须核对快照后的收款、退款、采购、续费和实例事实；未知任务禁止自动重放。

候选已接入HTTP、持久任务（独立于cron领导身份）、定时Task、续费/库存/CDN/附件回收/更新结果观察、目录同步与独立升级助手。恢复worker先Pause后隔离账户，显式人工放行才打开屏障。
取消context不会提前释放共享锁；必须等待业务函数实际退出。持久任务屏障覆盖领取、处理和完成状态写入。没有设置运行控制连接时HTTP和持久任务均拒绝受理。
候选实现和隔离测试不等同于全节点实际恢复演练通过。目录同步在维护期未取得准入时可能留下pending元数据，须补安全终态/重启核对；不能将其默认为成功。
仍须覆盖：长连接主动排空、控制连接丢失的取消行为、已发出的远端请求与旧执行者排空、所有后台任务。数据库账户隔离阻止继续写库，不能取消已到达第三方的请求。
数据库导入完成不等于恢复完成。2026-09-27 已在独立灾备 VM 使用真实 OSS 归档执行五次授权演练，未覆盖主开发 VM 数据：正常导入后保持待核对；SQL 导入失败与附件切换失败回滚；Redis 故障在导入后保持隔离；SQL 写入前强杀工作器后，重入拒绝未处理 journal。各次均保持应用停用、运行账户锁定、恢复屏障。

这组证据不覆盖任意 SQL 中段进程崩溃、真实第三方差异处理或最终生产放行，不作为完整业务 RTO。正常导入用时 22.714 秒仅为该归档和隔离环境的导入耗时。五次授权已用完；未决 journal 和 root 私有证据保留，不能删除 journal、解锁账户或直接把屏障改回 running 来绕过放行检查。故障场景之间的状态准备仅在应用停用、账户锁定的隔离演练中执行，不是生产恢复操作规程。
