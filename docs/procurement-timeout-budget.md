# 采购超时预算

仅 IDC Smart/Finance 采购使用专用出站客户端；保持供应商地址校验、DNS固定解析、禁止环境代理、响应大小限制和写请求重定向拒绝。

| 层级 | 时限 | 边界 |
|---|---|---|
| DNS/连接 | 10秒 | 保留既有目的地址校验，不因放宽业务等待而无限建连 |
| TLS握手 | 10秒 | 保留Go默认传输设置 |
| 采购单次请求（含响应体） | 60秒 | 响应头等待同为60秒，整体总时限仍优先；不再被普通客户端15秒响应头时限提前截断 |
| 整条采购/交付任务 | 5分钟 | 累计预算，不保证每阶段都可各用满60秒；继承更短调用方取消/截止时间 |
| 交付任务租约 | 6分钟 | 为取消后保存待确认状态、完成任务留出时间；失租仍进入unknown，禁止自动重放 |

实例只读的8秒、普通客户端30秒总/15秒响应头、其他任务2分钟/租约3分钟维持原行为。报价/配置上下文的更短外层预算仍生效。

生产采购不依赖浏览器或Nginx同步等待完成，因此不把PHP/Nginx历史3600秒设置全局照搬到Go。本次无DDL、无新增凭据/权限/环境配置，用户手动更新后仅对新执行采购生效，不重新激活历史unknown任务。

`CreateOrder`兼容入口也有5分钟累计上限。采购使用不复用连接的传输，避免过期连接导致传输层自动重放；适配器写调用继续单次发送。发出写请求后超时、断连、无效响应维持结果未知；保留已确认invoice检查点，禁止自动重复结算/付款/开通。只有已有“写入前报价失败”的安全重试判定可重试。

回归覆盖：真实本地HTTP加购和结算各20秒响应（均大于旧15秒）、缩短测试预算后的加购/结算/付款超时单次写入、调用方取消、断连/异常回复、发票检查点保存失败不付款、失租不重放、16路并发claim和多台交付幂等。所有模拟服务仅回环，数据库为无网络临时实例，不调用真实供应商。

本修复不代表已证实所有历史超时的网络根因；尤其11秒故障仍需后续分阶段脱敏证据核查。
