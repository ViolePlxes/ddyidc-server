# 后台更新拒绝切换时保持旧服务在线

触发：更新构建完成后，可用空间降至9550MiB，低于10240MiB切换门槛。独立助手返回失败，旧更新进程却在排队后350ms正常退出；Restart=on-failure不会拉起，因此页面500。

修复：后台不再主动退出，只有通过准入的独立助手负责停止旧服务及原子替换。拒绝切换仍保留旧API，由结果轮询登记失败、释放锁并恢复准备阶段推进的源码工作区。兼容旧助手已删除计划文件的失败结果，只从匹配的运行中后端任务恢复固定工作区；已完成/其他任务与前端不允许恢复。磁盘阈值保持10GiB，不绕过迁移、维护或权限门禁。

生产缓存维护：只清理已结束且回滚完成任务的.cache。复用回收器的全局Redis更新锁、本地文件锁、活动构建/进程引用检查、描述符相对删除及挂载/链接边界。无活动任务和待恢复计划时执行；不删除整个构建任务目录、候选程序、配置、数据库或备份。新版本原有长期资源回收机制仍随后台任务运行，不另建一套定时清理。

验证：新增低空间拒绝不调用systemctl、不替换程序的测试，以及普通/旧助手拒绝后的源码恢复和外来结果拒绝测试。完整VM构建、静态检查、回归与CI证据见交付记录。
