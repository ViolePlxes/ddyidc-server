# Finance 采购结算兼容与失败证据（2026-10-19）

## 范围与边界

候选后端 v0.1.141，基线 v0.1.140。仅修复 Finance 自动采购协议和失败记录；无表迁移、无余额/支付记账改动、无存量订单或机器回填，不重放既有 unknown 任务。

## 已核实与未核实

生产只读检查发现一次已付款采购进入 unknown，采购仅一次，本地未生成实例、未保存上游账单引用。原始错误被 Store.failProvision 的通用提示覆盖，审计未开启；历史响应不能从现有证据恢复。因此不把网络、余额不足或某一供应商响应形态写成已证实的该笔历史根因。

同配置只读报价验证正常，官方售价与订单预算一致，采购报价未超预算；未进行真实下单、付款、退款或机器操作。客户另外购买的替代机器不属于本次修复的数据操作范围。

本地 v10 备份中的 `public/plugins/server/idcsmart_common/logic/local_proxy/CommonCreateTrait.php::runFinanceCartFlow` 使用完整 `cart_data`，将 configoption 改名 configoptions；add 不设置 checkout，settle 不依赖返回 i。原 Go 实现却要求 i 且只传 pos[]，存在可确定复现的协议兼容缺口。参考源码来自本地备份，不访问旧 v10 服务器。

## 修复

- Finance add 不隐式 checkout；结算始终携带精确产品、周期、数量、配置、自定义字段、主机凭据和下游关联上下文。返回合法索引时保留 pos[]，没有索引时按 v10 的 cart_data 协议结算；不猜零、不清购物车、不结算整个购物车。
- 采购开始每个阶段先持久化检查点。检查点失败立即停止后续请求。
- 结算拒绝但含有效账单引用时先保存引用，然后停止。add 意外返回账单也只保存并转核查，禁止再结算。
- 采购写请求在 HTTP 401/403/405/429/500 时不自动重放；超时和异常同样保持 unknown 保护。只读报价仍可刷新认证。
- `contracts.ProcurementFailure` 提供白名单阶段/分类、HTTP/业务状态。数据库 last_error 和结构化日志仅记录安全分类与追踪编号；不记录原始错误文本、供应商消息、凭据或客户配置。原始 cause 只供内部 errors.Is/As，不作日志或 JSON 输出。

## 验证

VM 中使用受控 HTTP Finance 服务，采购无位置索引的三种正常响应和合法零索引均验证精确配置与单次开通；拒绝结算的账单保留、预算拦截、异常认证不重放、检查点失败停止后续请求、脱敏日志、超时/取消及慢结算均覆盖。

`TestDeliveryUnitsMySQL` 在官方迁移的临时 MySQL 中使用无索引响应贯通多实例交付、部分失败、未知结果不重购及人工只读恢复边界，并验证失败阶段与 HTTP 状态真实入库。不是第三方真实采购验收；不为验收另开收费机器。

部署证据、完整 commit、CI 与在线更新结果见交付记录；未完成发布前，不将候选代码写成已上线。
