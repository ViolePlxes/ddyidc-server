# Linux 性能基线与采购规格

## 2026-09-11 空闲基线

测试环境：Linux/amd64 Alpine 容器，DDYIDC 静态二进制连接本地测试 MySQL 8.0.36 与 Redis 7.2，独立监听 18080；现有 8080 服务未停止、未重启。`/health` 返回 database/redis 均为 true。

连续 6 次、每 3 秒一次的容器样本：

| 指标 | 结果 |
|---|---:|
| CPU 平均 | 0.27% |
| 内存平均 | 14.37 MiB |
| 内存范围 | 13.41–14.84 MiB |
| Linux 进程/线程计数 | 17–18 |

这是测试数据集下的空闲基线，只证明后端常驻开销低，不代表峰值并发容量。真实服务器上线后须分别在空闲、常规峰值和压测期间运行 `performance-baseline.sh`，并同时记录 MySQL 缓冲池命中率、慢查询、Redis 内存、磁盘延迟和 Nginx 请求时延。

## Linux 采购建议

- 起步：4 个专用 vCPU、8 GiB RAM、160 GiB 以上企业级 NVMe；磁盘长期保留至少 20% 空闲。
- 内存预算：MySQL buffer pool 2 GiB、Redis上限 512 MiB、Go API 空闲约 15 MiB，剩余供构建、页缓存、连接峰值、Nginx 和回滚产物。
- 推荐：并发量、更新构建频率或数据库增长较高时使用 8 vCPU、16 GiB RAM，并配置独立 300 GiB 以上数据/备份卷。
- 扩容线：CPU 持续超过 65%、available memory 低于 20%、存储延迟持续超过 10 ms，或磁盘达到 70% 预警线。

采购前仍需确认：峰值并发用户、每分钟订单/支付请求、当前数据库容量、月增长率、备份对象存储、域名与固定 SSH 出口 CIDR。
