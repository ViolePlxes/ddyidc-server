# 发布回退边界

程序回退不等于数据库恢复。更新助手只恢复它保存的可执行文件和源码 commit，
不会撤销 SQL 迁移、修改配置、删除订单、恢复余额或重新执行供应商请求。

## 允许自动回退的范围

在线更新前保留当前程序、完整 commit、配置的私有备份及迁移清单。
配置和密钥备份仅留在受限运维目录，不加入交付包或 OSS 业务备份。
在同一已核验 schema/业务状态契约内更新，启动或版本检查失败时，助手停止新服务、
恢复旧程序及源码，并重新检查健康、原 commit 和关键接口。任一检查失败，回退
标记为失败并停止未验证的服务；不能因健康 URL 返回 200 就宣布成功。

数据库脚本变更必须离线评审和迁移。在线更新提示有 SQL 变化不代表已执行迁移，
也不代表旧程序能够安全处理迁移后的业务状态。不要同时执行迁移和在线更新。

## 当前基础建设版本的兼容限制

- 后端 v0.1.39 新增收款核对、持久化任务、逐台交付、库存预留、事件收件箱和
  维护屏障（迁移 006–011）。低于此版本的程序缺少相应处理语义；不允许在已
  使用这些能力的库上直接降级到 v0.1.38 或更早版本。
- v0.1.40 相对 v0.1.39 仅增加测试采购的显式授权门禁，没有生产程序或 schema
  差异。后续版本是否兼容必须重新核对，不能根据版本号大小推断。
- 回退前暂停入口和新增外部副作用任务，核对收款、退款、采购、续费及未知结果。
  如果需要回到不兼容的 schema，按灾备恢复流程先备份、停写、隔离恢复并核对
  外部事实；未经核对不得放行或重新下单。原有资金流水和审计保留。

## 验证口径

测试环境应独立记录：新版本启动失败、HTTP 200 但 commit 不符、回退版本不符、
回退关键接口失败，以及成功恢复原版本。记录程序 SHA、前后 commit、服务状态、
迁移清单和关键业务计数。隔离空库的程序回退验证不能代替带业务数据的灾备恢复，
也不能当作生产部署验收。
